## Опишите задачу и требования к данным

Перед выбором резерва запишите, что нужно сохранить — русский язык, работу с кодом, длинный контекст, инструменты, изображения или локальное выполнение. Затем определите, какие данные разрешено отправлять внешнему поставщику.

Сделайте несколько небольших примеров собственной рабочей нагрузки. На них проще сравнить качество и задержку, чем по одному общему рейтингу модели. Добавьте случай с ошибочным вводом и случай с вызовом инструмента, если он нужен приложению.

## Рассмотрите облачные варианты

В качестве кандидатов можно изучить API DeepSeek, Qwen, GLM и Kimi. Для русскоязычных задач также существуют Yandex AI Studio и GigaChat. Проверяйте актуальные модели, доступность аккаунта, способы оплаты и правила обработки данных у каждого поставщика.

Название модели и название сервиса могут относиться к разным организациям. Разберитесь, кто обслуживает endpoint и хранит журналы. Для корпоративного проекта согласуйте нового поставщика с владельцем данных до переноса рабочего контекста.

## Подготовьте локальный вариант

Ollama позволяет запускать поддерживаемые модели на собственном устройстве. Начните с модели, подходящей по памяти и лицензии. На машине с небольшим объёмом RAM или видеопамяти учитывайте размер весов, квантование и длину контекста.

```sh
ollama list
ollama show ИМЯ_УСТАНОВЛЕННОЙ_МОДЕЛИ
ollama run ИМЯ_УСТАНОВЛЕННОЙ_МОДЕЛИ
```

Сверьте имя с установленной библиотекой моделей. Для воспроизводимого опыта запишите версию Ollama, модель, квантование и параметры контекста. Проверьте, какие компоненты вашего клиента продолжают обращаться в сеть за поиском, инструментами или обновлениями.

## Проверьте совместимость API

Сравните аутентификацию, схему сообщений, streaming, инструменты, ограничения контекста и формат ошибок. Сходный путь endpoint сам по себе не описывает совместимость всех функций. Для Claude Code используйте документированный маршрут подключения и поддерживаемые поставщиком возможности.

Сохраните настройки каждого провайдера отдельно. Во время переключения должны меняться endpoint, ключ и параметры выбранной модели. Проверьте, что повторная попытка не применяет внешнее действие дважды.

## Проведите контрольный запуск

Запустите подготовленный набор задач, оцените результаты и расходы. Сохраните понятный порядок переключения и возврата к основному сервису. Обновляйте этот опыт после существенного изменения клиента, шлюза или модели.

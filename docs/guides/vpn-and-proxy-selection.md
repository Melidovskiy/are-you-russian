VPS даёт управляемый сервер и выходной IP. Работа Claude зависит от всей цепочки соединения, включая клиент, DNS, прокси и доступность адреса у оператора.

## Что требуется от сети

Соединения Claude должны проходить по ожидаемому маршруту, в том числе при входе и обновлении сессии. Отдельно проверяются DNS, IPv4 и IPv6, поведение при отказе прокси и длительная передача ответа.

TCP-проверка порта показывает, что установилось TCP-соединение. Для оценки работоспособности нужны ещё TLS, авторизация и передача данных. Ответ сайта с IP также проверяет только запрос к этому сайту. Рабочая сессия Claude требует проверки самого клиента.

## Домены Claude

Маршрутизация должна учитывать несколько назначений. Основные примеры из документации Claude Code приведены ниже. [Требования Claude Code к сети](https://code.claude.com/docs/en/network-config).

| Домен | Назначение |
| --- | --- |
| `api.anthropic.com` | Запросы Claude API |
| `claude.ai`, `claude.com` | Вход в аккаунт Claude |
| `platform.claude.com` | Console и операции с OAuth-токенами |
| `sso.claude.com` | Вход организаций через SSO |
| `downloads.claude.ai` | Загрузка и обновление компонентов |
| `bridge.claudeusercontent.com` | Связь с расширением Claude in Chrome |
| `http-intake.logs.us5.datadoghq.com` | Необязательная операционная телеметрия |
| `browser-intake-us5-datadoghq.com` | Необязательные отчёты об ошибках |

Это примеры для понимания цепочки. Конкретные функции используют дополнительные адреса. Веб-версия и Desktop также загружают ресурсы с CDN и доменов пользовательского содержимого. Перечень требуется сверять с документацией используемого клиента. [Сетевые требования и дополнительные адреса](https://code.claude.com/docs/en/network-config#network-access-requirements).

Проверяйте маршрут для входа в аккаунт, загрузки вложения и открытия артефакта. Эти функции могут использовать разные хосты. Общая подсеть облачного провайдера может обслуживать несколько независимых сервисов. В документации Anthropic диапазоны для входящих подключений клиентов и для исходящих запросов платформы перечислены отдельно. [Сетевые требования Claude Code](https://code.claude.com/docs/en/network-config), [диапазоны Claude Platform](https://platform.claude.com/docs/en/api/ip-addresses).

## Репутация и доступность адреса

Один сервер может иметь несколько IP. Адрес, к которому подключается клиент, и адрес выхода в интернет могут различаться. Проверка порта относится к входу, а сайт с определением IP показывает выход.

Успешное соединение из одной сети не устанавливает доступность из другой. Проверка с домашнего интернета, мобильного оператора и самого VPS отвечает на разные вопросы. Смена DNS также решает задачу разрешения имён, а доступность IP проверяется отдельно.

## Почему здесь нет инструкции по развёртыванию

Грамотное развёртывание VPS — сложная задача. Она включает защиту управления, сертификаты, маршрутизацию, обновления, восстановление после сбоев и проверку поведения реальных клиентов. Несколько универсальных команд эту работу не заменяют. Объяснять её целиком в руководстве по проверке окружения Claude не имеет смысла.

Здесь важны требования к результату. Для отдельного окружения можно использовать [Claude Cage](../claude-cage/) с рабочим сетевым узлом.
